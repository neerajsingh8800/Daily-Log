# 08: Securing Autonomous Agent Tool Execution — Sandboxing, RBAC & AST Validation

Autonomous LLM agents leverage function calling and tool execution to interact with external databases, shell environments, APIs, and cloud infrastructure. However, enabling dynamic tool execution introduces critical attack vectors such as **Arbitrary Code Execution (ACE)**, **Command Injection**, **Privilege Escalation**, and **Confused Deputy Exploits**. When an agent ingests malicious third-party content, indirect prompt injections can coerce the agent into constructing arbitrary system calls or abusing its credentials.

This module covers security models for agent tool calling, role-based access control (RBAC), Abstract Syntax Tree (AST) static analysis, runtime sandboxing mechanics, and a production-grade Python Secure Tool Execution Engine.

---

## 1. Theoretical Foundations

### 1.1 Attack Surface in Agent Tool Execution

1. **Confused Deputy Problem**:
   * **Mechanics**: The agent possesses high-privilege credentials (e.g., cloud IAM roles or database write access). An attacker with lower privileges supplies an input or document containing an indirect prompt injection, tricking the agent into executing privileged actions on the attacker's behalf.
2. **Command & SQL Injection via Function Arguments**:
   * **Mechanics**: Attacker-controlled parameters passed to function calls are naively concatenated into shell commands or SQL queries without sanitization:
     ```python
     # Vulnerable Tool Execution
     os.system(f"ping -c 1 {user_supplied_host}")
     ```
3. **Unsanitized Dynamic Code Execution (`eval`/`exec`)**:
   * **Mechanics**: Agents generated python code (e.g., Data Interpreter agents) executed directly in the host environment without resource constraints or namespace isolation.

### 1.2 Defense In Depth: Micro-Sandboxing & AST Parsing

To securely execute code or dynamic function calls generated by LLMs, production environments enforce a multi-tiered defense:

1. **Abstract Syntax Tree (AST) Static Analysis**: Before executing any LLM-generated Python script, analyze its AST to block unsafe imports (e.g., `os`, `sys`, `subprocess`, `socket`), dynamic reflection (`eval`, `exec`, `__subclasses__`), and disk/network primitives.
2. **Role-Based Tool Access Control (RBAC)**: Enforce scoped permission matrices per session or user role, limiting which function signatures an agent can trigger.
3. **Containerized / MicroVM Isolation**: Run execution tasks inside lightweight container runtimes (e.g., gVisor, Firecracker microVMs, or Docker with restricted `seccomp` profiles and read-only root filesystems).

## 2. Tool Execution Architecture Comparison

| Security Control | Overhead | Isolation Level | Primary Vulnerability Blocked |
| :--- | :--- | :--- | :--- |
| **Naive Python `eval()` / `exec()`** | < 0.1ms | None (Host OS Compromise) | None |
| **AST Static Whitelisting** | < 1ms | Code Parsing Layer | Dangerous imports & dynamic reflection |
| **Docker / Seccomp Sandbox** | 50ms – 200ms | OS Process / Namespace | Host filesystem tampering & network exfiltration |
| **Firecracker MicroVM** | 5ms – 10ms (Cold start) | Hardware/Hypervisor | Kernel exploits & cross-tenant leaks |

### Python Implementation (secure_tool_execution.py)
```python
import ast
import inspect
from typing import Callable, Dict, List, Any, Optional, Set
from pydantic import BaseModel, Field


class ToolExecutionVerdict(BaseModel):
    is_success: bool
    tool_name: str
    result: Optional[Any] = None
    error_message: Optional[str] = None
    violation_reason: Optional[str] = None


class UserContext(BaseModel):
    user_id: str
    role: str  # e.g., "READ_ONLY", "ANALYST", "ADMIN"


class SecureToolRegistry:
    """Manages agent tool registration, RBAC enforcement, and AST safety validation."""

    # Banned AST modules and functions for generated Python code execution
    BANNED_IMPORTS: Set[str] = {
        "os", "sys", "subprocess", "shutil", "socket", "requests", 
        "urllib", "ctypes", "multiprocessing", "threading"
    }
    
    BANNED_BUILTINS: Set[str] = {
        "eval", "exec", "compile", "__import__", "open", "input", "help"
    }

    def __init__(self):
        self.tools: Dict[str, Callable] = {}
        self.tool_permissions: Dict[str, Set[str]] = {}

    def register_tool(self, name: str, allowed_roles: List[str]):
        """Decorator to register a function as a secure agent tool with RBAC rules."""
        def decorator(func: Callable):
            self.tools[name] = func
            self.tool_permissions[name] = set(allowed_roles)
            return func
        return decorator

    def validate_python_code_ast(self, code_str: str) -> Tuple[bool, Optional[str]]:
        """Static analysis of python code string using AST parsing to detect dangerous constructs."""
        try:
            tree = ast.parse(code_str)
        except SyntaxError as e:
            return False, f"Syntax Error in generated code: {str(e)}"

        for node in ast.walk(tree):
            # Check for banned import statements
            if isinstance(node, ast.Import):
                for alias in node.names:
                    if alias.name.split('.')[0] in self.BANNED_IMPORTS:
                        return False, f"Forbidden import detected: '{alias.name}'"
            
            elif isinstance(node, ast.ImportFrom):
                if node.module and node.module.split('.')[0] in self.BANNED_IMPORTS:
                    return False, f"Forbidden import from module detected: '{node.module}'"

            # Check for banned builtin function calls
            elif isinstance(node, ast.Call):
                if isinstance(node.func, ast.Name) and node.func.id in self.BANNED_BUILTINS:
                    return False, f"Forbidden function call detected: '{node.func.id}'"

        return True, None

    def execute_tool(
        self,
        tool_name: str,
        arguments: Dict[str, Any],
        context: UserContext
    ) -> ToolExecutionVerdict:
        """Executes registered tool after validating RBAC permissions and parameter types."""
        # 1. Check if tool exists
        if tool_name not in self.tools:
            return ToolExecutionVerdict(
                is_success=False,
                tool_name=tool_name,
                violation_reason=f"Tool '{tool_name}' is not registered."
            )

        # 2. RBAC Access Control Check
        allowed_roles = self.tool_permissions[tool_name]
        if context.role not in allowed_roles:
            return ToolExecutionVerdict(
                is_success=False,
                tool_name=tool_name,
                violation_reason=f"Access Denied: User role '{context.role}' cannot invoke '{tool_name}'."
            )

        # 3. Parameter and Code Safety Inspection
        target_func = self.tools[tool_name]
        
        # If argument contains raw Python code targeting an interpreter tool, run AST check
        if "code" in arguments and isinstance(arguments["code"], str):
            is_ast_safe, ast_error = self.validate_python_code_ast(arguments["code"])
            if not is_ast_safe:
                return ToolExecutionVerdict(
                    is_success=False,
                    tool_name=tool_name,
                    violation_reason=f"AST Security Violation: {ast_error}"
                )

        # 4. Safe Tool Execution
        try:
            res = target_func(**arguments)
            return ToolExecutionVerdict(
                is_success=True,
                tool_name=tool_name,
                result=res
            )
        except Exception as e:
            return ToolExecutionVerdict(
                is_success=False,
                tool_name=tool_name,
                error_message=f"Runtime Tool Execution Error: {str(e)}"
            )


# -------------------------------------------------------------------
# SIMULATION / VERIFICATION RUNNER
# -------------------------------------------------------------------
if __name__ == "__main__":
    registry = SecureToolRegistry()

    # Define registered agent tools with RBAC roles
    @registry.register_tool(name="query_database", allowed_roles=["ANALYST", "ADMIN"])
    def query_database(query_str: str) -> List[Dict[str, Any]]:
        # Simulated database query execution
        return [{"id": 101, "status": "ACTIVE", "query": query_str}]

    @registry.register_tool(name="execute_python_calculator", allowed_roles=["ANALYST", "ADMIN"])
    def execute_python_calculator(code: str) -> float:
        # Safe math evaluation after AST inspection passes
        allowed_globals = {"__builtins__": None, "abs": abs, "min": min, "max": max, "sum": sum}
        local_vars = {}
        exec(code, allowed_globals, local_vars)
        return local_vars.get("result", 0.0)

    # Simulation Contexts
    user_read_only = UserContext(user_id="user_123", role="READ_ONLY")
    user_analyst = UserContext(user_id="analyst_999", role="ANALYST")

    print("=== Test 1: RBAC Violation Attempt ===")
    verdict1 = registry.execute_tool(
        tool_name="query_database",
        arguments={"query_str": "SELECT * FROM metrics;"},
        context=user_read_only
    )
    print(f"Success: {verdict1.is_success}")
    print(f"Violation Reason: {verdict1.violation_reason}\n")

    print("=== Test 2: Valid Tool Execution ===")
    verdict2 = registry.execute_tool(
        tool_name="query_database",
        arguments={"query_str": "SELECT * FROM metrics;"},
        context=user_analyst
    )
    print(f"Success: {verdict2.is_success}")
    print(f"Result : {verdict2.result}\n")

    print("=== Test 3: AST Injection & Banned Import Interception ===")
    malicious_code = "import os\nos.system('echo HACKED')"
    verdict3 = registry.execute_tool(
        tool_name="execute_python_calculator",
        arguments={"code": malicious_code},
        context=user_analyst
    )
    print(f"Success: {verdict3.is_success}")
    print(f"Violation Reason: {verdict3.violation_reason}")
```

## 4. Operational Best Practices

* Enforce Principle of Least Privilege (PoLP): Provision short-lived access tokens (e.g., AWS STS or OAuth2 scoped tokens) per tool execution step rather than binding master service credentials to the long-running agent runner.
* Network Namespace Isolation: Execute code execution workloads inside containers with network access completely disabled (docker run --network none) unless explicitly required by the tool contract.
* Strict JSON-Schema Parameter Validation: Validate all LLM function call payloads against static Pydantic / JSON Schemas prior to executing function logic to prevent type confusion or parameter pollution.
